# snipperting - Snippets tool for Windows
Save text snippets and easily access them from SysTray icon.
Windows application, accessed via menu from SysTray.
The process is a Windows GUI app: no console when launched from Explorer or the Start Menu.
Edit's WebView2 maps the on-disk `web/` folder to `https://snipperting.example/` so Monaco can load its scripts. One process at a time (named mutex).
Snippet files, the tray menu, preferences, help, and about are native.
Written in Go, using Justfile for command runner, ships with installer for ease of use.
Installs somewhere local for user, for example some %LOCALDATA% sub-folder.
Application keeps basic config in JSON file, next to installed executable. 
Config JSON is generated by application on first startup, it's not shipped.

## Icons
App logo source of truth is `assets/logo.svg`. Meat Bag owns it. Clanker never modifies leftover `assets/logo.png` or `assets/logo.af`. Logo recolor is Meat Bag-ordered. Four snip strokes, bottom to top: sky `#8ECAE6`, teal `#219EBC`, amber `#FFB703`, orange `#FB8500`. Navy `#023047` is UI background, not a stroke, so the tray ico stays visible on dark taskbars.
Derive copies with Just: `just icon` rasters the SVG to `build/snipperting.ico` for the tray icon and native window icons (title bar, taskbar, Alt-Tab, installer). `just docs-logo` copies the SVG to `docs/logo.svg` for GitHub Pages. Pages show `docs/logo.svg` as an image (stroke colors as drawn), not a `currentColor` mask. Pages also use that file as the tab favicon (`rel="icon"`). The Windows `.ico` keeps the SVG stroke as drawn.
`assets/logo.png` stays in the tree as a leftover; do not copy it into `docs/` or `web/`.
Other icons used by `snipperting` shall be taken from Tabler.io/icons and vendored into project.

## SysTray menu
The tray icon uses a **native Windows menu** (left-click and right-click). It must not open a web window for the snippet list.
SysTray menu shows list of snippets, and sub-categories of snippets.
When a snippet is clicked in the menu, it fires its configured action.
Action can be configured per snippet (editor / Preferences Bulk Edit).
Available actions are:
- Clipboard - place snippet content in clipboard so it can be pasted
- Inject - inject the snippet at cursor position, wherever it might be. The app remembers the last foreground window that is not snipperting (and not the Windows tray), so a tray click still pastes into that window.
- Enable/Disable - Gray out the snippet in the menu, it will be listed but can't be clicked (set in Bulk Edit)

Subfolder opens a native submenu to the side.
At each menu level, snippet files are listed first, then folders (submenus). Nested submenus use the same order. Then the footer separator.
Footer items under a separator:
- Edit
- Preferences
- Help
- About
- Exit

Edit, Preferences, Help, and About are native windows. They use the brand palette (no Windows accent): sky `#8ECAE6`, teal `#219EBC`, navy `#023047`, amber `#FFB703`, orange `#FB8500`. Light: bg sky, field/chip fill matches bg, text navy, muted/rule teal (border, not fill), accent orange, accent text navy. Dark: bg navy, field/chip fill matches bg, text sky, muted/rule teal (border, not fill), accent amber, accent text navy. Pressed native controls still fill accent. Theme is system / light / dark (default system, tracks Windows). Monaco and rendered markdown follow that same setting. GitHub Pages uses the same tokens (light default, dark via `prefers-color-scheme`). Edit's right pane is one WebView2: Monaco for note tabs, rendered HTML for a Preview tab. Help's content pane is WebView2 showing rendered MANUAL.md (`NavigateToString`). The snippet list itself is the native tray menu.
About is a native window: app logo, name, Version (nearest git tag at build from `git describe --tags --abbrev=0`, prefixed with v), Commit (short hash, `-dirty` when the working tree was dirty at build), the tagline, and Website and GitHub buttons. Builds with no tags show Development build instead of a version. Website opens `https://iamtew.github.io/snipperting/` and GitHub opens `https://github.com/iamtew/snipperting` in the default browser.

Tray items for snippets, folders, Edit, Preferences, and Help use vendored Tabler icons (rasterized to `.ico` for the native menu).

## Data folder
Snippets data is stored in plain text files, markdown, with .md file extension.
Location is stored in config file, default snipperting data folder is `~/.snipperting`
Each file is a snippet, and should be listed as one entry in the menu.
Data dir can have sub-folders, these will be shown as categories, sub-menus, in the snipperting systray menu.

## File format
Snippets can have a header, that won't be included when injecting or copying info clipboard.
Example: `demo-snippet.md`

```md
----
label: Demo Snippet (label will be used instead of filename in menu, if it's configured).
about: Description of the snippet displayed when hovering an item in the menu, kinda like alt-text.
action: inject/clipboard - action that fires when clicked.
state: enable/disable, on/off, true/false. a bool, can be updated by clicking menu button.
hidden: true/false - bool, hides item from menu.
----
# Snippet example title
Wow a snippet body, so fancy!
```

## Editor
Edit is modeled on VS Code: native file tree plus Monaco, with a status bar under the text. Native chrome (tabs, format bar, explorer icons) stays.
The editor is a native window. The file list is a native tree of the data dir (all `.md` files, including hidden, and empty folders). Folders nest with indent and Tabler file/folder icons, like a file explorer. At each indent level, folders are listed first, then files. Tree items show on-disk names (the `.md` file name, the folder name). The tray menu still uses the snippet `label` when set.
New note, New folder, and Save are left-aligned Tabler icons on the explorer; Delete is right-aligned on that same row (not a window-wide text toolbar). New note and New folder use the selected folder, or the folder of the selected file. They insert a placeholder row and turn that label into an edit field (Enter commits, Esc cancels). Defaults: `untitled.md` / `New folder` (add `-2` if that name is taken). Esc or an empty name drops the placeholder; nothing is written. Enter writes a `.md` with the default `----` header (notes) or creates the folder, then opens a new note. Delete removes the selected note or folder after a native Yes/No confirm; a folder takes its contents with it. Open tabs for deleted paths close without a second save prompt.
Right-click on the tree opens a native context menu. On a file: New note, New folder, Rename, Save, Delete. On a folder: New note, New folder, Rename, Delete. On empty tree space: New note, New folder (data dir root). New note and New folder still use the clicked item’s folder, same rule as the toolbar.
Rename is the same in-place label edit on the existing row (F2 or context menu). Clicking a selected item does not start a rename. Files keep `.md` if omitted. If the destination already exists, a native error box says so and the name stays. Drag a file or folder onto a folder to move it there; drop on a file uses that file’s parent; drop on empty tree space is the data dir root. A move into itself or a descendant is refused. Open tabs follow the new paths.
Native tabs keep several notes open. Each tab has a close control on the tab itself. Closing a dirty tab (or the window) prompts before discard. Ctrl+S saves the active tab. Save is also the floppy icon on that explorer row.
With no note tab open, the text pane is the theme background (sky / navy), not a white editor, and says to open a note from the list on the left.
A native markdown format bar (bold, italic, strikethrough, heading, quote, lists, code, link) is left-aligned over the editor and wraps the Monaco selection. A second click of the same format control removes those markers. It does not live in the WebView. Preview is a Tabler icon right-aligned on that same row.
When a note is open in Monaco, a status bar under the text shows `Ln X, Col Y`, `(N selected)` when a range is selected, `UTF-8`, `LF` or `CRLF`, and `Markdown`. Display only. Hidden on the empty pane and on Preview.
Preview opens a native tab (title like `Preview · note.md`) that shows the current buffer rendered as markdown in the same WebView. The snippet `----` header is omitted, same body as inject/clipboard. The preview tab is never dirty and is not written to disk. Closing the note closes its preview. Switching back to the note tab restores Monaco. Not a system browser.
The text pane is one WebView2 child of that window. Monaco follows the Preferences theme; preview HTML does too.
Launched from the tray menu, it opens on the file tree. Save writes the `.md` file, header included.

## Preferences
Preferences is a native window where we configure Snipperting.
Things to configure, starting out:
- Data directory: Location.
- Clipboard notice: on/off (default on).
- Theme: system / light / dark (default system).
- Bulk Edit

### Data directory: 
Where all snippets are stored, default `~/.snipperting`.
Preferences shows the current path and a Browse button. Browse opens the native Windows folder picker. Picking a folder writes `dataDir` in config.json and refreshes Bulk Edit. Cancel leaves the path unchanged.

### Clipboard notice:
When a snippet action copies to the clipboard, a small native on-screen notice says it was copied. It must not steal focus. Default on. A checkbox in Preferences enables or disables it. Inject does not show this notice.

### Theme:
Three push-like buttons: System, Light, Dark. The selected one is pressed. System follows Windows light/dark. Applies at once to native windows and Monaco. Stored as `theme` in config.json.

### Bulk Edit:
Change things in bulk over multiple snippets. 
Snippet settings such as state, action, hidden. 
This will update the settings in each and every snippet file.
Looks like a labeled list, and every row has:
- left aligned: filename
- right aligned:
  - action: two push-like buttons, Inject and Clipboard; the selected one is pressed
  - state: on/off
  - hidden: on/off
Subfolders are displayed folded, can be unfolded to view items, are indented in display. At each indent level, snippet files are listed first, then folders (same grouping as the tray menu).
Empty data dir shows an empty-state line.

## `./docs` folder, website and documentation
The `./docs` folder shall contain a website for GitHub pages.
Think product page, explaining the application.
The product page links to a rendered manual (`manual.html`). That page loads `MANUAL.md` in the browser and renders it (title and intro, then table of contents, heading anchors). `MANUAL.md` is the source.
The product page and the manual header link to GitHub: source repo, latest release, and the issue tracker. Those links use vendored Tabler icons (`docs/vendor/tabler/`). Both pages set `docs/logo.svg` as the favicon.
The manual shall also be shipped inside snipperting executable and be possible to viewed by user under Help menu item. Help renders MANUAL.md (not source) with the document title and intro first, then a table of contents whose links jump to heading anchors.
